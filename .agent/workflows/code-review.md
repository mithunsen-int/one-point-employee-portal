# Workflow: /code-review

> **Methodology reference:** sdd-methodology.md **#30** (Gate 2 checklist and Security Checklist, applied in full every time), **#5** (Principle 7 — "a human is accountable for every merged line, regardless of who typed it. 'The agent wrote it' is not a defence"), **#14** ("no agent-signature suffixes in commit messages... a commit message referencing a task ID is traceability, not attribution, and is encouraged"), **#18** ("Consistency with existing codebase patterns — a human-eye check .ai-context/architecture.md alone doesn't guarantee"). Security checks grounded against `.ai-context/constitution.md`'s Security Posture and `.agent/rules/int-standards.nextjs.md` **#9** (Security Guidelines — MongoDB query-filter sanitization, no hardcoded secrets).

**Purpose:** Runs the Gate 2 code-review pass over one task's diff, applying the full Gate 2 checklist and Security checklist — every item, every time, regardless of diff size. Records the outcome as an appended row in a single running per-feature evidence file. This workflow drafts the review; it never grants the merge.

**Usage:** `/code-review <feature-slug>.T0<n>` — or, since this project does not use slash commands, via its prompt file: `@code-review.md for <feature-slug>.T0<n>`.

## Preconditions

1. No diff/code change exists for `<feature-slug>.T0<n>` — stop; there is nothing to review.
2. `<feature-slug>.T0<n>` has no stated "Acceptance: `<AC IDs>`" line in its tasks.md entry — stop; a review cannot verify ACs it can't identify.

## Steps

1. Read `<feature-slug>.T0<n>`'s entry ("Acceptance: `<AC IDs>`") and the full text of each linked AC from the spec.
2. Verify each linked AC individually, by ID, against the diff — not "looks reasonable"; an explicit per-ID pass/fail.
3. Apply the full Gate 2 checklist (**#30**), every item, every time:
   - Each AC verified individually against the diff, by ID
   - No AI-attribution in comments or commit messages — task-ID references (e.g., "Implements `<feature-slug>.T03`") are fine and encouraged, per **#14**; do not flag these as attribution
   - Security checklist (below) passed
   - `architecture.md` / ADR updated if this diff warrants it
   - Tests were written first and confirmed Red before Green, not retrofitted — cross-check against the recorded Red-confirmation output of `/generate-tests` for this task
   - `status.md` and the spec's Status updated same day
   - Standard review otherwise applies: readability, naming, DRY, and consistency with existing codebase patterns (**#18** — a human-eye check nothing else guarantees)
4. Apply the full Security checklist (**#30**), every item, every time:
   - No PII in logs at any level
   - No secrets, credentials, or tokens hardcoded or logged
   - All new/changed endpoints have an explicit rate-limit decision — cross-check against the plan's stated decision
   - New dependencies vetted (maintained, real, approved) before entering the manifest
   - Auth boundaries and least-privilege checked, not assumed
   - Data-at-rest and in-transit handling matches `constitution.md`
   - No client-supplied object passed unvalidated into a MongoDB query filter (NoSQL injection) — per int-standards.nextjs.md **#9**
   - SAST/DAST and dependency scan run and clean, or exceptions explicitly signed off
5. Explicitly flag any AI-attribution language in a comment or commit message ("Generated by...", "AI-written," etc.) as a Blocking finding — distinct from, and never confused with, a task-ID reference, which must be confirmed fine.
6. Compile findings, each tagged Blocking / Should-Fix / Note.
7. Append one new row to `.ai-context/gate-reviews/gate2-evidence-<feature-slug>.md` — a single running evidence file per feature. Create the file with a header if it does not yet exist. Never overwrite or remove a prior row.
8. Close with this fixed statement, unmodified: "This review may be drafted by an AI agent, but only a named human reviewer can mark `<feature-slug>.T0<n>` Merged."

## Output

- A findings report: every Gate 2 and Security checklist item marked Pass / Fail / N-A with a one-line justification each.
- One appended row in `.ai-context/gate-reviews/gate2-evidence-<feature-slug>.md`: `Task ID | Date | Reviewer (named human) | Verdict | Blocking findings (if any) | Reference to full report`.
- The fixed human-Merge-authority closing statement.

## Do not

1. Do not mark `<feature-slug>.T0<n>` Merged — only a named human reviewer can do that, this workflow never does (**#5.7**).
2. Do not create a new evidence file per task — append to the single running per-feature file.
3. Do not flag a task-ID commit reference as AI-attribution — that is traceability, explicitly permitted.
4. Do not skip any Gate 2 or Security checklist item because the diff "looks small" or "obviously fine" — every item, every time.
